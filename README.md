# Soc.Ai

Social media page using an LLM for content generation

# 1. Goal

The goal of this project is to create a social media-like platform where content (posts, comments, threads) is generated by an AI model and visualized through a React + TypeScript frontend.

# 2. High-Level Architecture

The system consists of three main components:

## 2.1 Backend (Content Generation Service)

- Language: TypeScript (Node.js / Express)
- Database: MongoDB
- AI Model: Open-source LLM (e.g., GPT-NeoX, LLaMA, etc.)
- Responsibilities:
  - Generate users, posts, comments, and threads based on user-defined prompts or randomly.
  - Store generated content in MongoDB.
  - Provide REST APIs for frontend interaction.

## 2.2 Frontend (Content Visualization)

- Language: React + TypeScript
- Styling: Tailwind CSS
- Responsibilities:
  - Fetch generated content from backend APIs.
  - Display posts, comments, and threads in a user-friendly UI.
  - Provide filtering and sorting options for browsing content.

## 2.3 Communication Protocol

- REST API: Communication between Frontend and Backend.
- JSON Format: For data exchange.

# 3. Requirements

## 3.1 Backend Requirements

- Setup:
  - Initialize a Node.js + TypeScript project.
  - Use `Express` for API handling.
  - Connect to `MongoDB` for data storage.
- Database Schema:
  - Users, Posts, Comments, Threads collections.

### Database Schema (MongoDB)

1. **Users Collection:**

```json
{
  "_id": "ObjectId",
  "username": "string",
  "profilePicture": "string",
  "bio": "string"
}
```

2. **Posts Collection:**

```json
{
  "_id": "ObjectId",
  "userId": "ObjectId",
  "content": "string",
  "createdAt": "Date",
  "comments": ["ObjectId"]
}
```

3. **Comments Collection:**

```json
{
  "_id": "ObjectId",
  "postId": "ObjectId",
  "userId": "ObjectId",
  "content": "string",
  "createdAt": "Date"
}
```

4. **Threads Collection:**

```json
{
  "_id": "ObjectId",
  "commentId": "ObjectId",
  "userId": "ObjectId",
  "content": "string",
  "createdAt": "Date"
}
```

### Relationship Between Database Objects

1. **Users**

   - Users create Posts, Comments, and Threads.
   - One-to-Many relationships with Posts, Comments, and Threads.

2. **Posts**

   - Created by Users.
   - Contains multiple Comments.
   - One-to-Many relationship with Comments.

3. **Comments**

   - Created by Users in response to a Post.
   - Contains multiple Threads (replies).
   - One-to-Many relationship with Threads.

4. **Threads**
   - Created by Users in response to a Comment (not directly to a Post).
   - One-to-One relationship with a parent Comment.
   - No further nesting of Threads (can be extended later).

### Example Scenario

- A user makes a post: _"What's the best programming language?"_ (Saved to `Posts`)
- Another user comments: _"I think Python is great for beginners."_ (Saved to `Comments`)
- A thread is created replying to the comment: _"I agree, but it also scales well for advanced projects."_ (Saved to `Threads`)

## 3.2 Frontend Requirements

- Setup:
  - Initialize a React + TypeScript project using Vite.
  - Apply Tailwind CSS for styling.

### UI Components

1. **Home Page:**

   - Display a feed of posts.
   - Sorting and filtering options.

2. **Post View:**

   - Display individual post content.
   - Display comments and threads.

3. **User Profiles:**

   - Display user info and their posts.

4. **Navigation:**
   - Header and sidebar for navigation.

### API Integration

- Use Axios or Fetch API to interact with backend endpoints.
- Display data dynamically from backend responses.

### Styling

- Tailwind CSS for styling consistency.
- Responsive design for various screen sizes.

# 3.3 Content Generation Service

- AI Model Integration:
  - Utilize an open-source LLM to generate content.
  - Provide endpoints to trigger content generation (posts, comments, threads).

# 3.4 Social Media Data Populator

- Use the generation service to create any number of Users with a highly detailed bio that will be used
  as context to the LLM when creating posts for that specific user
- Select a User that exists and create a post belonging to the User
- Select a User that exists and create synthetic interactions with some number of available posts and comments
  that would mimic a traditional day of social media usage
